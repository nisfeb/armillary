# Armillary Phase 6: the Talon provider

**Goal:** an `Armillary` provider in Talon. The user adds it once; Talon asks the armillary desk on the user's own ship for the inference config, the balance and the plans, offers top-ups and the subscription through the ship's checkout, and runs every AI feature that picks it through the leased key or the vendor's proxy. The store copy that promises no backend is rewritten. This work lives in the talon repo (`~/software/personal/talon`, canonical GitHub `nisfeb/talon`), on a new branch `feat/armillary` cut from `nisfeb/feat/orrery-client` (1.8.0-rc23, which contains every ai-settings commit; the local checkout on `master` is two years stale, never build on it). sneagan merges the branch himself; do not merge. The armillary side is done through phase 5: the customer ship's routes this brief calls are `GET /api/inference`, `GET /api/account[?fresh=1]`, `GET /api/plans`, `GET /api/catalog`, `POST /api/checkout`, `POST /api/keys`, `POST /api/lease`, `DELETE /api/lease`, `POST /api/cancel-subscription`, all under `/apps/armillary` over the ship cookie, documented in `~/software/personal/armillary/README.md` and `docs/channel.md`, `docs/payments.md`, `docs/leases.md`.

**Working rules:** one implementer, one review at the end. Talon's own rules in its `CLAUDE.md` hold (capability flags at the boundary, common first, `Mutex` not `synchronized` in commonMain, lean gradle invocations, no attribution, `~/software/personal/talon` git identity nisfeb, fetch and push through `ssh://git@ssh.github.com:443/nisfeb/talon.git` with `GIT_SSH_COMMAND='ssh -i ~/.ssh/nisfeb -o IdentitiesOnly=yes'` since port 22 times out). Desktop compiles and tests are the gate (`./gradlew :composeApp:desktopTest --tests '*Armillary*'` and the existing AI tests); Android and iOS must compile (`:composeApp:compileDebugKotlinAndroid`, the iOS Kotlin target); no device run is required. A live check against the fake customer ship `~feb` (`http://localhost:8081`, cookie in the session scratchpad, its armillary desk pointing at `~wex`) is the last step.

## The facts of the branch, from the 2026-09-20 survey

- Providers live in `ai/AiProfile.kt`: `enum class ProviderKind(label)` with `OpenRouter`, `Anthropic`, `OpenAi`, `OpenAiCompatible("A server of your own")`, `ThisDevice`; `AiProvider(id, kind, label, baseUrl, apiKey, models: List<ModelInfo>, offersJev)`; `ModelInfo(id, name, zdr, tools, contextLength, speech)`; `ModelRef(provider, model)`; `AiProfile(providers, defaultModel, features, jev)` with `resolve(f)`; stable ids `"main"`, `"private"`, `"device"`, `"speech"`.
- The clients (`AiClient.complete`, `AgentClient.completeWithTools`, `CallRecordingPublisher.sttFrom`) dispatch on the legacy `AiSettings.Provider` reached through `providerOf(kind)` in `AiSettings.Config.forFeature`; `providerOf` answers `null` for an unmapped kind and `forFeature` then returns the config unchanged. `Custom` throws `error("Custom provider requires a model name")` when the model is null and normalizes a base URL by appending `/chat/completions` unless present.
- Cost: `usage: {include: true}` is sent only when `cfg.provider == OpenRouter`; `usageCost` reads `usage.cost` for everything but Anthropic; `AiSpend.add(feature, usd)` keeps this month's spend per feature.
- Model fetching per kind is `ai/ModelCatalog.kt` `fetch(p)` and `check(p)`; `shipBase()` answers the base the ship's generator may call, `null` for unknown kinds.
- Sync: `forSync()` strips keys and model lists from the profile blob; `ProviderKind` is `@Serializable`, and an older build decoding an unknown enum value drops the whole profile in `profileAfterEntry`. `keepingLocal` carries a local key only when id and kind match.
- The screen is `ui/screens/AiSettingsSection.kt` inside `SettingsScreen`'s `SettingsTab.Ai`: `ProviderCard`, `AddProvider` (a hardcoded `listOf(OpenRouter, Anthropic, OpenAi, OpenAiCompatible)`), `providerSummary`, `FeatureRow`, `ModelPicker` with `Private` and `ZDR` badges, `readingWarning`.
- The ship client to copy is `orrery/OrreryApi.kt`'s owner half: `session.http` (cookie-scoped), `root = shipUrl.trimEnd('/') + APP_PATH`, the `send`, `reading`, `request` trio, `sealed class OrreryError { Refused, Unreachable, Garbled }`, `probe()` mapping 404 to `MISSING` and 403 to `SIGNED_OUT`, `OrreryRepo.attach(shipUrl, ship)` with `StateFlow`s, `ui/GrubberyApps.kt`'s `orreryRow()` with `install = null`, `AppsSettingsScreen` rows and `LocalUriHandler.current.openUri(...)`.
- Store copy promising no backend: `store/privacy-policy.md`, `store/description.md`, `PRIVACY.md` (root, the distributed one), `store/data-safety.md`, and two advisory lines in `RELEASE.md`.

## 1. The ship client

`composeApp/src/commonMain/kotlin/io/nisfeb/talon/armillary/ArmillaryApi.kt`, `OrreryApi`'s owner half copied and renamed: `APP_PATH = "/apps/armillary"`, `sealed class ArmillaryError { Refused(status, reason), Unreachable(cause), Garbled(cause) }`, `enum class ArmillaryAvailability { UNKNOWN, PRESENT, MISSING, SIGNED_OUT }`, `probe()` on `GET /api/account`. Data classes and readers, hand-rolled `kotlinx.serialization.json` tree walking as orrery does: `data class Inference(mode: String, baseUrl: String, key: String, models: List<String>)` from `GET /api/inference` (404 with `no key yet` is a distinct `NoKey` outcome, 404 otherwise is `MISSING`); `data class Account(balanceMicro: Long, plan: String, subscriptionActive: Boolean, renews: String?, vendor: String, stale: Long, leaseHeld: Boolean, leaseDisabled: Boolean, checkouts: List<Checkout>)` from `GET /api/account` and `?fresh=1`; `data class Plan(id, name, kind, priceMicro, creditMicro, interval)` from `GET /api/plans`; `data class CatalogRow(id, provider, inMicro, outMicro, tags: List<String>)` from `GET /api/catalog`; `data class Checkout(nonce, url, status, rail, amountMicro)`; `suspend fun checkout(rail: String, plan: String?, amountMicro: Long?): CheckoutAnswer` (`Url(url)` on 200, `Pending(nonce)` on 202, `Refused(reason)` on 502); `suspend fun mintKey(name: String): Boolean` (`POST /api/keys`; 202 is `false`); `suspend fun lease(): Boolean` (`POST /api/lease`; 404 or 501 is `false`, since a vendor without leases or a desk older than phase 5 answers those; 502 throws `Refused`); `suspend fun dropLease()`; `suspend fun cancelSubscription()`. `fun money(micro: Long): String` renders dollars to two places, `"under a cent"` below 5.000, the way `AiSettingsSection.money` does.

`ArmillaryRepo.kt`, `OrreryRepo`'s shape: `attach(shipUrl, ship)` per session, `StateFlow`s `availability`, `error`, `account`, `plans`, `catalog`, `inference`, `refreshing`; `suspend fun refresh(fresh: Boolean = false): Result<Unit>` (probe, then inference, account, plans and catalog in that order, each `runCatching`, a missing route leaves its flow alone); `suspend fun ensureKey(deviceName: String): Result<Inference>`: `inference()`, and on `NoKey` first `lease()` then `mintKey("Talon on $deviceName")` then `inference()` again, polling every two seconds for up to thirty; `suspend fun topUp(rail, plan, amountMicro): Result<String>` answering the URL, then a background poll of `account(fresh = true)` every five seconds for two minutes so the balance appears without a tap; `suspend fun subscribe(planId, rail = "stripe")` the same. Wiring: where `OrreryRepo` is attached and detached (`compose/App.kt`, `ui/TalonApp.kt`, `androidMain/OrreryWorker.kt` is NOT needed: no background work). Tests in `commonTest/armillary/ArmillaryApiTest.kt` over fixtures for every reader, `NoKey` detection, the 202 checkout answer, `money`.

## 2. The provider kind

In `ai/AiProfile.kt`: `ProviderKind.Armillary("Armillary")` (the label is one string; sneagan may rename the offering later), `const val ARMILLARY_PROVIDER = "armillary"` beside the stable ids, `AiProvider.isPrivate` unchanged (false), `shipBase()` answers `baseUrl` for `Armillary` (in lease mode that is OpenRouter's base and the ship's generator can use the leased key; in proxy mode the vendor's proxy, also OpenAI-shaped). `providerOf(Armillary)` is `AiSettings.Provider.Custom`, so `forFeature` fills `baseUrl` and `apiKey` from the provider row, which `ArmillaryRepo` keeps current: every successful `inference()` writes `baseUrl`, `apiKey` and `models` (as `ModelInfo` with `zdr` from the catalog's tags) onto the `armillary` provider row through `aiSettings.setProfile` (an `edit` that touches only that row). A `ModelRef` on the Armillary provider with a blank `model` resolves to the first listed model, never blank, so `Custom`'s `error("Custom provider requires a model name")` cannot fire; a unit test proves it. `forSync()` also drops every `Armillary` provider from the blob, and `keepingLocal` re-adds the local one: the key is per ship and per device (each device asks its own ship), and an older build must never decode the new enum value (a test in `AiProfileSyncTest` encodes a profile with an Armillary provider and decodes it with a `ProviderKind` copy lacking the value, proving the blob carries none).

In `ai/AiClient.kt` and `ai/AgentClient.kt`: send `"usage": {"include": true}` when the config's provider kind is Armillary as well as OpenRouter (thread the kind through the `Config`, or match on the base URL host `openrouter.ai` plus the `armillary` provider id; prefer a `Config.usageInclude: Boolean` derived in `forFeature`), and `usageCost` reads `usage.cost` for it (already the default branch). `ModelCatalog.fetch(Armillary)` answers the models from the provider row (they come from the ship, not from a `/models` call), and `check(Armillary)` calls `ArmillaryRepo.refresh(fresh = true)` and answers `"Answers in N ms."` or the error. `readingWarning` for an Armillary model: when the mode is `proxy`, "Your messages go through the vendor's ship to the model. A ZDR model does not keep them, the ship does not store them."; when `lease` and the model is ZDR, null; else the existing text. `CallRecordingPublisher.sttFrom` leaves Armillary out of transcription in this phase (the proxy has no audio route).

## 3. The card

In `ui/screens/AiSettingsSection.kt`: `AddProvider`'s list gains `Armillary` (one at most: hidden when the profile already holds the `armillary` id); adding it creates `AiProvider(ARMILLARY_PROVIDER, Armillary, "Armillary")` and calls `ensureKey`. `ProviderCard`'s Armillary branch: no address field, no key field; a status line from `availability` (`Answering on this ship.`, `Not on this ship. The feature rows and `ModelPicker` need no change: Armillary's models appear under its label with a `ZDR` badge where the catalog says so. `AppsSettingsScreen` gains `armillaryRow()` in `ui/GrubberyApps.kt` (`install = null`, the orrery texts with the name changed) and a pointer line "Armillary is a provider under AI." when present. `desktopTest/ui/AiSettingsSectionTest.kt` gains the card's three states; `GrubberyAppsTest` gains the row mapper.
